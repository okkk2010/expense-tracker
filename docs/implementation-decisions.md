# 초기 구현 선택과 후속 조정

사용자는 남은 네 가지 질문을 지금 더 결정하지 않고 개발을 진행하도록 요청했습니다. 다음은 사용자의 확정 답변과 구분한 변경 가능한 초기 구현입니다.

| 항목 | 초기 구현 |
| --- | --- |
| 첫 화면 지표 | 월 지출, 일별 추이, 종목별 지출, 금융수단별 지출을 표시합니다. 사용자 요청에 따라 홈의 태그 예산·최근 기록 요약과 장식·홍보 영역을 제거하고, 예산과 거래 관리는 전용 메뉴에서 제공합니다. |
| 금융수단 | 초기 네 항목은 편집 가능한 기본값입니다. 설정에서 추가·이름/설명/색상 수정·보관/해제하며 미사용 항목은 삭제할 수 있습니다. 보관 시 새 거래에서 제외하고 과거 내역과 해당 월 지출 집계는 유지합니다. 기존 DB를 자동 마이그레이션하고 구형 백업도 복원합니다. |
| 태그 중복 | 총지출은 거래 한 건을 한 번만 계산합니다. 태그별 수치는 겹칠 수 있음을 구분합니다. 예산은 태그별 계산을 확인할 수 있게 합니다. |
| 태그 삭제 | 과거 연결을 유지하는 보관과 과거 연결도 지우는 삭제를 구분해 선택하게 합니다. |
| 저장본 수정 후 저장 | 새 저장본 생성과 기존 저장본 갱신을 구분해 제공합니다. |

입력 주간 고정, 수입·잔액 강제 연결, 투자 기록, 오프라인 입력, 핀 버튼 등의 요구를 새로 추가하지 않습니다. 현재 투자 계획 없음·온라인 전제·핀 불필요는 사용자의 명시적인 답변에 따른 것입니다.

프론트와 백엔드 배포를 분리하므로 프론트 소스에는 DB나 모델 서비스 비밀키를 두지 않습니다. 개인 접속키는 계정 없이 본인 기기에서 서버를 연결하기 위한 구현 선택입니다. 서비스 공개 회원가입을 추가하지 않습니다.

## PC와 모바일 거래 입력

PC에서는 엑셀처럼 여러 거래를 표에 이어 입력하는 흐름을 사용합니다. 1024px 이상에서 입력 창을 열면 셀 이동, 행 추가·복제, 여러 셀 붙여넣기, 일괄 저장을 제공하며 거래 목록도 표로 표시합니다. 모바일은 날짜를 선택한 뒤 거래를 추가하는 기존 폼과 목록을 유지합니다. 작성 중 화면 크기가 바뀌어도 입력한 내용을 잃지 않도록 열린 입력 방식은 창을 닫을 때까지 유지합니다.

붙여넣기는 날짜·유형·금융수단·종목·메모·태그·금액 순서입니다. 금융수단·종목·태그는 기존 항목을 이름이나 ID로 찾으며 임의로 생성하지 않습니다. 빈 행을 제외한 최대 500건을 검증 후 한 번에 저장합니다.
