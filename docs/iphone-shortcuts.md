# iPhone에서 토스·KB 알림을 모아에 기록하기

이 기능은 개인용입니다. 아이폰이 선택한 앱의 알림을 단축어로 전달하면 모아 서버가 거래 정보를 해석합니다. 은행 API 로그인이나 오픈뱅킹 계약을 사용하지 않습니다. 은행 앱의 전체 거래내역을 읽거나 과거 알림을 일괄 가져오는 기능은 아닙니다.

모아의 **설정 → iPhone 자동 수집**에서 연결과 수집함을 관리합니다. 같은 화면의 **토스 단축어 설치**, **국민은행 단축어 설치** 버튼으로 아이폰에서 서명된 `.shortcut` 파일을 받습니다. [설치 절차](../shortcuts/README.md)에 따라 각 연결의 수집 전용 헤더 값을 입력하고, 알림 앱·본문 입력·자동 실행 권한은 본인의 아이폰에서 지정합니다. 파일에는 실제 키가 들어 있지 않습니다. iCloud 공유 링크는 발급하지 않았습니다.

## 1. 서버 준비

1. Node.js 24로 모아 백엔드를 실행합니다. 기존 실행법은 [README](../README.md), 배포는 [배포 안내](deployment.md)를 참고하세요. 새 기능은 프론트엔드와 백엔드를 모두 업데이트해야 사용할 수 있습니다.
2. Docker Compose는 프로젝트 최상위 `.env`, 직접 실행은 `backend/.env`에서 `APP_ACCESS_TOKEN`을 읽습니다. 운영 서버에서 이미 사용하는 개인 접속키는 유지합니다. 이 키가 없으면 수집 연결을 만들 수 없습니다.
3. 운영 프론트 `https://expense-tracker-lake-eight-39.vercel.app`의 모아 설정에서 **서버 API 주소 `/api`**와 기존 개인 접속키를 저장합니다. Vercel은 `/api/*` 요청을 `http://115.68.223.74:8000/api/*`로 전달합니다.
4. 아이폰 Safari에서도 `https://expense-tracker-lake-eight-39.vercel.app/api/health`에 접속할 수 있는지 확인합니다. 서버의 80·443 포트는 이 Vercel 프록시 연결과 별개입니다.

단축어에 넣을 운영 수집 주소는 **`https://expense-tracker-lake-eight-39.vercel.app/api/shortcuts/ingest`**입니다. 앱 설정의 `/api`는 브라우저용 상대 주소이므로 단축어에는 위처럼 전체 HTTPS 주소를 넣습니다. 인증 헤더에는 반드시 별도로 발급한 수집 전용 키를 사용합니다.

`localhost`와 `127.0.0.1`은 단축어가 실행되는 **아이폰 자신**을 가리킵니다. PC 주소로 자동 변환되지 않습니다. 같은 Wi-Fi 개발 테스트는 PC의 사설 IP에 서버를 바인딩해서 사용하고, 외부에서는 본인만 접근할 수 있는 HTTPS 서버 또는 사설 VPN 경로를 사용하세요. 이 기능은 방화벽·공유기 포트·공개 터널을 자동으로 열지 않습니다. 서버가 꺼졌거나 네트워크가 끊기면 전송할 수 없습니다.

## 2. 금융수단별 연결 만들기

1. **설정 → iPhone 자동 수집**에서 수집 연결을 추가합니다.
2. 출처로 **토스** 또는 **KB스타뱅킹**을 선택합니다.
3. 실제 금융수단을 직접 지정합니다. 기존 `국민카드`는 `국민은행 통장`과 다릅니다. 필요한 통장은 **금융수단 추가**로 새로 만듭니다.
4. 알림에 실제로 표시되는 계좌 별칭이나 마스킹 번호 등, 해당 수단을 구별할 문자열을 입력합니다. 카드 끝 4자리만 같은 경우에는 더 구체적인 문자열을 사용합니다. 토스 앱 하나에서 여러 은행·카드의 알림을 받는다면 수단별로 연결을 나눕니다.
5. 기본 종목·태그를 정하고, **자동 기록은 처음에는 꺼 둡니다.**
6. 생성 후 표시되는 **수집 전용 키**를 단축어 설정에 보관합니다. 전체 거래 조회·수정용 개인 접속키를 단축어에 넣지 않습니다. 수집 전용 키는 생성·재발급 시에만 표시됩니다. 잃어버리면 재발급하고 기존 단축어의 키도 바꿉니다.

연결 이름은 구별하기 쉽게 `토스 · 생활비 카드`, `KB · 생활비 통장`처럼 정할 수 있습니다. 출처 앱과 실제 금융수단은 별도로 저장됩니다.

## 3. iOS 버전에 맞게 자동화 만들기

사용자는 **iOS 27.2로 업데이트했습니다.** 토스·KB의 앱 푸시는 ‘알림’ 자동화로 연결하고 실제 본문 전달 여부를 확인합니다. [설치용 단축어](../shortcuts/README.md)를 사용하면 수집 주소·인증 헤더·JSON 전송 동작을 다시 만들 필요 없이, 설치할 때 키를 입력하고 알림 본문을 연결할 수 있습니다.

iOS 26.6처럼 앱 알림 실행 조건을 제공하지 않는 버전에서는 실제로 수신하는 결제·입출금 SMS를 ‘메시지’ 자동화로 보내야 합니다. 토스나 KB가 해당 계좌·카드에 SMS를 제공하는지는 각 서비스에서 확인해야 하며, 푸시만 오는 거래는 메시지 자동화로 수집할 수 없습니다.

앱 알림 자동화는 이를 제공하는 iOS 27 계열에서 별도로 설정·검증합니다. [Apple의 단축어 버전별 기능 안내](https://support.apple.com/ko-kr/149045)는 iOS 27의 ‘새로운 자동화’에 ‘알림’을 명시합니다. 문서상의 기능 존재와 토스·KB의 실제 본문 전달·자동 실행 검증은 구분합니다. 모아가 아이폰 업데이트를 자동으로 수행하지는 않습니다.

아이폰의 단축어 앱에서 **알림(Notification)** 실행 조건이 제공되는지 먼저 확인하세요. 지원 버전에서는 특정 앱과 알림 제목·부제·본문 조건을 선택할 수 있습니다. iOS 버전에 따라 새 단축어의 편집 메뉴에 자동화가 있거나 별도의 자동화 화면에 있습니다. 해당 실행 조건이 없다면 일반 앱의 푸시 알림을 이 방법으로 수집할 수 없습니다. 이 경우 실제로 수신하는 은행 SMS를 대상으로 **메시지** 자동화를 만들거나 CSV·직접 입력을 사용합니다.

토스와 KB스타뱅킹에 **각각** 아래 구성을 만듭니다. 서로 다른 수단에 같은 알림을 중복 전달하는 자동화는 만들지 마세요.

### 실행 조건

- 앱: 해당 연결의 **토스** 또는 **KB스타뱅킹**.
- 필터: 해당 금융수단을 구별하는 문자열을 본문 또는 제목에 설정합니다.
- 광고·추천·잔액 안내만 있는 알림은 대상에서 제외합니다.
- 자동 실행을 허용합니다. 실행 전 확인 또는 잠금 상태 실행 옵션이 보이면 본인이 원하는 자동화 권한을 설정합니다. 개별 동작의 첫 접속 허용도 필요할 수 있으므로 처음에는 잠금 해제 상태에서 실행합니다. 잠긴 상태 실행은 실제 기기로 별도 확인합니다.

### 전송 동작: ‘URL 콘텐츠 가져오기’

| 항목 | 값 |
| --- | --- |
| URL | 모아 연결 화면에서 복사한 전체 수집 주소. 현재 운영 주소: `https://expense-tracker-lake-eight-39.vercel.app/api/shortcuts/ingest` |
| 메서드 | `POST` |
| 헤더 `Authorization` | `Bearer ` 다음에 해당 연결의 수집 전용 키. 공백 1개 필요 |
| 헤더 `Content-Type` | `application/json` |
| 요청 본문 | `JSON` |

JSON 필드를 추가하고, 알림의 변수를 다음처럼 연결합니다. **‘알림 본문’ 같은 안내 문장을 직접 입력하면 안 됩니다.** 변수 선택기에서 실제 알림 입력을 선택하고 제공되는 속성을 지정합니다.

| JSON 키 | 값 | 필수 |
| --- | --- | --- |
| `body` | 알림 입력의 본문/Body | 필수 |
| `title` | 알림 입력의 제목/Title | 선택 |
| `subtitle` | 알림 입력의 부제/Subtitle | 선택 |
| `source_app` | 알림을 보낸 앱 이름 또는 고정값 `토스` / `KB스타뱅킹` | 선택 |
| `occurred_at` | 알림의 날짜가 제공된다면 ISO 8601로 변환. 예: `2026-10-31T12:30:00+09:00` | 선택·권장 |
| `event_id` | 원래 알림의 안정적인 고유 ID가 실제로 제공될 때만 사용 | 선택 |

없는 속성은 빈 안내 문구를 보내지 말고 해당 JSON 필드를 생략합니다. 필수 `body`가 비면 등록되지 않습니다. `occurred_at`은 가능한 한 원래 알림의 날짜를 사용하세요. 같은 알림을 재전송하면서 현재 시간이나 임의 UUID를 새로 생성하면 동일 이벤트 판별이 어려워집니다. 거래 날짜를 알 수 없으면 서버가 한국 시간 기준 수신일을 사용합니다. 자동 기록을 켜기 전에 실제 거래일과 일치하는지 확인하세요. 지연된 알림은 수집함에서 확인 후 기록하는 방식이 안전합니다.

메시지 자동화를 사용하는 경우에는 `body`에 단축어 입력의 실제 문자 내용을 연결합니다. 제목·부제·앱·알림 날짜 속성이 제공되지 않으면 생략합니다.

## 4. 확인 후 자동 기록 켜기

1. 자동 기록을 끈 연결로 먼저 시험합니다. 단축어 편집기의 수동 실행은 원래 알림 입력이 없을 수 있으므로, 별도의 테스트용 텍스트를 `body`에 연결해서 전송할 수 있습니다.
2. 테스트용 가상 문구: `토스뱅크 체크카드 1234 승인 12,500원 모아테스트상점 10/31 12:30 잔액 987,000원`. 이는 실제 토스·KB 알림 형식을 보증하는 예시가 아닙니다.
3. 모아 수집함에 **확인 필요**로 나타나는지 확인합니다. 테스트 항목은 **제외**하고 실제 거래로 기록하지 않습니다.
4. 테스트용 고정 문구를 제거하고 다시 실제 알림 변수를 연결합니다.
5. 실제 새 거래 알림에서 금액·날짜·금융수단이 정확한지 확인합니다. 계좌 잔액이나 누적 사용액을 결제금액으로 읽지 않는지도 봅니다.
6. 확인된 연결만 **자동 기록**을 켭니다. 식별 문자열이 있어야 하며, 명확한 결제 승인 외의 내역은 계속 확인함에 남을 수 있습니다.

## 5. 기록 결과와 예외

| 서버 응답 `status` | 의미 |
| --- | --- |
| `recorded` | 실제 거래로 기록됐고 기존 통계에 반영됩니다. |
| `pending` | 알림을 보관했습니다. 모아 수집함에서 내용을 확인·수정한 뒤 기록하거나 제외합니다. |
| `duplicate` | 이미 받은 알림으로 판별됐습니다. 같은 거래를 다시 만들지 않습니다. |

단축어에서 응답의 `message`를 읽어 결과를 확인할 수 있습니다. 매 거래마다 안내가 필요 없다면 ‘결과 보기’처럼 사용자의 조작을 기다리는 동작을 넣지 않습니다. 수집 실패 시에는 성공한 것처럼 처리하지 마세요. 이 저장소는 아이폰의 재전송 큐나 네트워크 복구 시 자동 재전송 기능을 설치하지 않으므로, 실패한 알림은 원래 내용·날짜를 유지한 채 직접 재전송하거나 직접 입력해야 합니다.

- 금융수단 식별 문자열이 없거나 맞지 않으면 자동 기록되지 않습니다.
- 여러 금액·외화·금액 누락·승인 실패·광고·이체·ATM 출금·카드대금 정산·취소·환불 등은 확실한 결제로 자동 처리하지 않습니다. 취소·환불은 새 수입이나 지출로 기록할 수 없으며, 원거래를 직접 정정한 뒤 해당 알림을 제외합니다.
- 국민은행 계좌 출금은 카드 승인 알림과 달리 소비인지 이체·정산인지 구분하기 어려울 수 있어 확인이 필요할 수 있습니다.
- 다른 출처에서 비슷한 결제가 들어오면 중복 가능성을 확인합니다. 같은 금액이라는 이유만으로 별개의 실제 결제를 무조건 합치지 않습니다.
- 같은 카드 결제의 알림과 통장 출금이 각각 왔다면 실제 소비는 한 번만 기록합니다. 신용카드 사용과 다음 달 카드대금 납부도 구분합니다.
- 수집 전용 키로는 전체 가계부를 조회·수정할 수 없습니다. 연결을 끄거나 키를 재발급하면 기존 키로 새 알림을 받을 수 없습니다.
- JSON 백업에는 재사용 가능한 접속키가 포함되지 않습니다. 복원한 연결은 꺼진 상태로 시작합니다. 수집키를 재발급해 단축어에 반영한 뒤 수집을 다시 켜고, 필요하면 자동 기록도 별도로 켭니다.

## 현재 확인 범위

서버·웹 기능은 자동화 테스트와 로컬 브라우저로 검증합니다. 사용자의 아이폰에서 토스·KB의 실제 알림 본문 전달, 잠금 상태 실행, 네트워크 접속, 최초 권한 동의는 별도로 확인해야 합니다. 알림이 발생하지 않은 거래와 과거 내역까지 모두 자동 수집된다고 보장하지 않습니다.
